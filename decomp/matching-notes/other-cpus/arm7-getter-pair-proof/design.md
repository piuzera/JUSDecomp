# Finite getter-pair proof boundary

The single-getter capsules each kept the other getter opaque. This capsule asks
whether both accepted MW objects can coexist at their adjacent original
placements, with one shared WRAM symbol and complete original-image equality.
A single public `replay(output: Path) -> Path` operation owns the result. It
returns the receipt only after every compile, original read, native link, and
negative control passes. Failed runs retain private diagnostics and produce no
completed receipt.

Two implementation files keep that interface small. `reproduce.py` checks
package/tool pins, compiles the unchanged C sources, and writes the receipt.
`pair.py` owns the closed low/high contract, checked original mappings, actual
object parsing, native construction, and ELF/map readback. No registry, plan
module, external wrapper, or alternate candidate interface is needed.

The one contract owns each role's source/hash, function, expected actual object,
code/pool extent, placement, and observed relocation operands. The recipe owns
tool identities and fixed options. The capsule owns the pinned checked-layout
copy and original window manifest. An immutable four-field binding value holds
SUBPRIV, shared WRAM, IRQ, and system values; every supplied binding is checked
against actual linked symbols in each trial.

Original checked mappings and the adjacent contract rows derive opaque ranges,
selectors, map physical addresses, preserved image intervals, and shared-pool
negative positions. The producer associates each real object hash with its
argv input, exact map row, linked function, and linked bytes. That association
prevents an apparently complete image from concealing an omitted or misplaced
getter role.

The implementation retains the selected two-file boundary. Original names,
ABI, extent, compiler/SDK identity, and source ownership remain unproved.
