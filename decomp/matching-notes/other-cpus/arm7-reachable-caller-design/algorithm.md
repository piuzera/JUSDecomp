# Boundary and graph decisions

The proposed Python owner knows process provenance and graph composition. The Rust observer still owns checked ROM mapping and V4T decoding. A frozen audit document is never a checked input. This operation has to capture a successful run of the reviewed observer before privately parsing that run's stdout.

Snapshot the original ROM, pinned layout, observer binary and complete approved source context, composer source and imported local helper closure, explicit spans and root evidence before execution. Create a fresh contained directory without symlinks. Generate the span manifest from immutable requests, capture its size/hash, invoke the existing observer's five arguments, and retain command, stdout, stderr and successful exit. Rehash every input afterward. A fresh run must cover each requested program/region/mode/range exactly once. Reject unexpected selections or program identities, unsupported schema/CPU/ISA, missing instructions, duplicated starts, noncontiguous instruction coverage, transfers without their source start, and inconsistent source program. Keep literal instruction text as a diagnostic string, never parse it to derive an edge.

The approved producer's accepted source context is authority for semantics not independently expressible at the Python boundary. Python may validate a received target's program/CPU/region equality and known wire variants; it cannot claim to have recreated `Arm7ModuleInput` or `CheckedArm7Envelope`. Root evidence is caller-supplied and pinned. The observer JSON does not expose the checked entry accessor, complete initialized/BSS ranges, or raw span byte digests. Those limitations are visible in the scope. No mutable-sidecar entry reread or guessed checked-root adapter is allowed.

Use an index keyed by full program identity, CPU, mode and instruction start, with region recorded on each node. Build a separate interval inventory from the emitted starts and lengths. Duplicate or overlapping same-mode selections fail atomically. Opposite-mode overlap is an explicit disputed interval: quarantine every instruction whose byte extent intersects it, keep that evidence in the audit, and stop roots and incoming edges at `mode_conflict`. Never pick whichever observation appeared first. Entire observed instructions remain the units of composition; blocks are unnecessary for this bounded caller.

For each accepted transfer, preserve the observer kind, guard and source condition. Unknown targets produce `unknown_transfer`. BSS and unresolved mappings stop regardless of numeric address. An initialized target may join only an exact same-program/CPU/region/mode start in another supplied observation and outside every disputed interval. If it lies inside an emitted instruction, stop at `instruction_interior`. If only the opposite mode supplies it, stop at `mode_conflict`. Otherwise keep `outside_selection`. Recompute selection membership across the complete supplied batch; an observer's local `outside_selection` label can become a cross-selection join. A local `instruction_interior` conflict cannot be promoted by adding an overlapping interpretation.

Roots must reference a program present in the operation and carry pinned evidence. Exact starts seed traversal. An interior root stops; a root touching disputed modes stops. A root absent from every decoded instruction stops at `unobserved_root`, without asserting whether it is BSS or outside initialized bytes. The current CLI cannot supply that ownership fact for an arbitrary root. A foreign-program root is an invalid request, not a matching address in another program.

Use one visited set of instruction keys and a queue per program. Preserve all reached guarded edges, including edges to already visited starts. Reaching a start through several guards keeps those incoming edges while processing its successors once. The maximum successful work is the finite supplied instruction count; selected bytes bound the producer input. Add a fixed operation resource ceiling with an explicit `work_limit` stop if the caller supplies too much input. There is no call stack, return inference, path-condition solver, skipped-byte classification or recursive decode. Calls have a callee edge and a separately guarded continuation. An indirect transfer cannot acquire a target from unrelated literal evidence.

Run parent and child fixtures separately even when their bytes match. The grounded direct-call path reaches `0x037fced4` then stops at `0x037fd02c`; its call-return continuation separately stops at `0x037fced8`. The startup BLT keeps its edge back to `0x02380020` and its guarded frontier at `0x0238002c`. The startup `BX r1` remains unknown. A loop edge is retained without expanding indefinitely.

Recheck immutable capture and input/artifact inventory before returning a graph for publication. Audit output contains source bytes0, functions unknown, executability unknown, relocations unknown, T10false and no function-end or coverage fields. Crash recovery means a fresh operation in a new directory; historical JSON is inspection evidence only. No production verifier stage or ROM packing path is added.
